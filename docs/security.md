# Security decisions and operations

Implemented controls include Argon2id, purpose-bound protected OTPs, durable server sessions, CSRF, explicit CORS, Helmet headers, hashed network/account rate limits, admin MFA, encrypted MFA/credential/outbox data, private uploads, signature checks, ClamAV quarantine, ownership checks, independent review evidence, audit trails, constrained preference ranks and transactional/idempotent scheduling.

Production must set fresh independent `SESSION_SECRET`, `OTP_PEPPER` and `DATA_ENCRYPTION_KEY`, HTTPS `APP_URL`, an explicit frontend allowlist, exact trusted proxy hops, real SMTP/Google/S3 settings and an institution-approved `PRIVACY_NOTICE_VERSION`. Secrets must come from a secret manager or injected environment. Production S3 should enforce server-side encryption, TLS, least privilege and blocked public access. Local MinIO credentials are deliberately limited to local development. Test that the chosen storage provider supports the requested AES256 encryption mode before release.

Session expiration and security event auditing are active. Expired sessions/rate buckets are removed by the worker. OTP/verifier history remains subject to the deployment's data retention policy. Sent email payloads are erased after delivery. `DOCUMENT_RETENTION_DAYS` configures the operator retention report; it does not authorize silent deletion of identity documents, appeals or historical evidence. Run `npm run retention:report` to count aged/replaced/closed-account records without displaying their contents. Institution-approved deletion, legal holds, subject access/export, objections, institutional review/appeal procedures and key rotation need operational implementation before a production launch.

No automatic legal compliance claim is made. Kenya's Data Protection Act and institutional rules require a qualified institutional privacy/legal review: lawful basis, purpose/necessity of national identity data, consent wording where appropriate, notices, retention schedules, data-subject rights, cross-border processing/storage, processor contracts, incident response, access review and whether a DPIA is required. Date of birth and extracted identity numbers are not collected automatically. Fields not needed for phase one remain absent. Review notes must avoid unnecessary personal information.

Admin bootstrap trusts an authorized infrastructure operator and verifies email ownership out of band. Losing all MFA factors requires a verified institutional recovery process; there is no public bypass. Every consequential admin API mutation is audited. Database administrators can alter data by virtue of their infrastructure role, so production database grants and independent audit exports must enforce the institution's separation of duties.

Workers use bounded BullMQ retries and retain failed jobs for inspection. Alert on old PENDING outbox items, QUARANTINED/FAILED scans, failed-job counts and worker downtime. After repairing a provider outage, an authorized operator can use `npm run jobs:retry` to retry retained failed jobs. Dispatchers discover pending database intent again after Redis loss. Email delivery is at least once: a crash after SMTP acceptance and before marking SENT may duplicate mail. Stable Message-ID helps downstream systems deduplicate, but exactly-once SMTP delivery is not claimed. Storage failures fail closed; orphan cleanup after a failed upload/cleanup is an operational reconciliation task.

Malformed and overly large inputs fail before business operations. File signature validation and antivirus are defense in depth, not proof of document authenticity. Downloads are always attachments and verify the stored digest. No provider verification URLs are automatically fetched. No identity numbers, uploaded bytes, tokens, OTPs, passwords or internal storage keys are logged.

Deployment checks: test backup restores, restrict PostgreSQL/Redis/object/scanner ports, keep malware signatures current, monitor storage encryption and lifecycle rules, lock runtime images to reviewed digests, scan containers/dependencies, test actual SMTP/Google login and failure recovery, perform an independent penetration test, verify cross-origin cookies/CSRF behind the real reverse proxy, and approve competency frameworks. Docker Compose is a development convenience, not a production deployment policy.

Production dependency auditing is part of CI. Both production and full dependency audits were clean at validation. A patched minimatch override is used for development tooling and verified by lint and tests; re-evaluate the override when upstream tools adopt the patched major version. Do not automatically force incompatible dependency downgrades suggested by npm.
