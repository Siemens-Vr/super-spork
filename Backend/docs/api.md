# API and Swagger

`PATCH /applicants/me` accepts only `legalName`, `phone`, `country` and `discipline`. Profile responses omit the retired region, education level, institution, professional status, graduation year and summary fields. A phone and discipline satisfy profile completeness; qualification details are collected through `/documents`.

For the one-career assessment lifecycle, contextual rubrics, assessor completion, skill gaps and learning progress, see [assessment targets and upskilling](assessment-targets.md).

The authoritative OpenAPI 3.1 definition is `docs/openapi.yaml`, generated by `npm run docs:generate` from request validators and explicit response definitions in `scripts/generate-openapi.ts`. `/api/v1/openapi.json` serves it as JSON; `/docs` serves Swagger UI when `ENABLE_SWAGGER=true`. Swagger adds a current CSRF token to state-changing Try it out requests. Disable public Swagger in production if the institution does not want the API explorer exposed.

Success responses contain `data` and optional pagination `meta`. Registration and code requests return `202`. Creates return `201`, including an idempotent booking retry returning its original resource. Logout and session revocation return `204`. Lists that grow without bound accept `page` and `limit` (default 20, maximum 100). Document lists return the most recent 100 private records. Slot queries span at most 90 days and return at most 2000 candidate slots.

```json
{
  "data": {
    "bookingId": "a-resource-uuid",
    "status": "SCHEDULED",
    "startsAt": "2026-12-01T06:00:00.000Z",
    "endsAt": "2026-12-01T07:00:00.000Z",
    "timezone": "Africa/Nairobi"
  }
}
```

The example above is an illustrative response shape; only a successful database transaction creates a real booking. Full confirmations also contain applicant, role, pinned blueprint/version, duration, instructions and event history.

```json
{
  "error": {
    "code": "SLOT_UNAVAILABLE",
    "message": "This assessment slot is full",
    "requestId": "a-request-uuid"
  }
}
```

Use a persistent cookie jar and obtain a new CSRF token after login/MFA/reauthentication. Do not send a Bearer token; these are server-side sessions. Include a distinct `Idempotency-Key` for booking and rescheduling. Retry a timed-out request with the original key and body. Schema validation is strict on writable bodies; applicant IDs, roles, password hashes, storage keys and review outcomes cannot be mass-assigned.

Multipart uploads derive the title from the uploaded filename, except `OTHER`, which requires a descriptive `title`. Course/programme and certification names are stored separately from the filename.

| Category                               | Required multipart fields                                                                             |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `NATIONAL_ID`, `PASSPORT`              | `category`, `file`                                                                                    |
| `BACHELOR`, `MASTER`, `DIPLOMA`, `PHD` | `category`, `courseName`, institution selection/name, `file` (certificate), `transcripts` (1–5 files) |
| `SHORT_COURSE`                         | `category`, `courseName`, `file` (certificate); provider/institution optional                         |
| standalone `TRANSCRIPT`                | `category`, `courseName`, institution selection/name, `file` (transcript)                             |
| `INDUSTRY_CERTIFICATION`               | `category`, `certificationName`, `issuer`, `issuedAt`, `file`; expiry optional                        |
| `PROFESSIONAL_REGISTRATION`            | `category`, `issuer` (professional-body name), `issuedAt`, `expiresAt`, `file`                        |
| `OTHER`                                | `category`, `title` (descriptive name), `file`                                                        |

Populate the searchable institution dropdown using `GET /api/v1/institutions?search=...&page=1&limit=20` (verified session required). Send either the selected `institutionId` or a typed `institutionName`, never both. Typed names are stored on the document, not automatically published in the institution catalogue. Responses include `institutionName` for both selection modes.

Institution search matches both full names and aliases/abbreviations (for example `search=JKUAT`). Optional filters are `type=UNIVERSITY|COLLEGE|TRAINING_INSTITUTE|OTHER` and `offersTvet=true|false`; each result includes its type and TVET flag. Keep the type filter optional in the frontend so applicants can search without knowing the classification. The seeded Kenyan directory contains 313 institutions from a recorded source snapshot; inclusion is not an accreditation determination. Run `npm run db:seed:institutions` to install/update just this directory, or `npm run db:seed` for the complete application seed. The institution seed preserves inactive entries and existing document links and can be rerun without duplicates. Source and cleanup details are recorded in `prisma/data/README.md`.

Repeat the `transcripts` multipart field for each transcript file. Each transcript is a private `Document` with its own scan/review state and a `qualificationId` linking it to the certificate. Upload, detail and list responses include attached `transcripts`. Replacement degree/diploma uploads require new transcripts; old files remain linked to the old qualification for history. Database records are created atomically, and staged objects are cleaned up on failure.

Select `category` in Swagger **Try it out**. The form exposes all metadata fields; the category requirements table describes which ones apply. The backend returns `422` with field-specific details when required metadata is missing. The frontend should show category-specific fields and populate its institution autocomplete from `/institutions`; Swagger does not load lookup options from another endpoint automatically. Degree and diploma uploads do not require `issuedAt` or `expiresAt`. An issue/award date may be supplied if known; leave expiry blank for these qualifications. Optional date fields may be omitted, empty or whitespace-only. When supplied, dates must use `YYYY-MM-DD` or an ISO datetime, and expiry must follow issue. Do not submit Swagger placeholder values such as `string` as dates.

For example, a master's submission contains these text parts plus certificate/transcript file parts:

```text
category=MASTER
courseName=Mechatronics Engineering
institutionId=<ID returned by GET /institutions>
file=<certificate.pdf>
transcripts=<year-1.pdf>
transcripts=<year-2.pdf>
```

For an unlisted institution, replace `institutionId` with `institutionName`. A professional registration instead sends `category=PROFESSIONAL_REGISTRATION`, `issuer=Engineering Board`, `issuedAt=2026-01-01`, `expiresAt=2028-12-31`, and one certificate in `file`.

Accepted file types are detected PDF, JPEG and PNG with matching MIME type, up to `MAX_UPLOAD_MB` (10 by default) **per file**. Every attachment is quarantined until scanning passes. Identity categories only use identity upload/replacement routes; other categories use `/documents`. Downloads work through `/documents/:id/download` for certificates and transcripts as well as identity files. Existing documents retain their metadata; the new name requirements apply to new uploads and replacements. Apply migrations and regenerate Prisma before restarting the API and worker after upgrading.

Admin routes always require a granular permission and recent MFA. Review requests are structured historical decisions, never Boolean toggles. Activation may change independently from blueprint content; published versions stay stable. Every consequential admin change records an audit row.

See [journey.md](journey.md) for a full curl workflow and [authentication.md](authentication.md) for Google linking/admin enrollment. Health probes are outside the versioned API. Readiness checks PostgreSQL and Redis; storage, scanner, SMTP and worker health also need deployment monitoring.
